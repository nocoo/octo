# Round 3：词索引、问句召回与用量新鲜度

## 范围与决策

- 词索引和查询共用原生中文分词；补充去重汉字单字，保留 trigram 的受限子串补充。优先 AND，只有严格匹配为空时按 BM25 放宽到 OR；不混加两个 tokenizer 的原始 BM25。
- 所有 memory 生命周期变更与词索引同一 D1 batch，标签改名/合并同步更新。回填不是 memory 内容写入，不新增版本或变更事件；无变化更新也不为索引元数据制造写入。
- 用量与审计原子增量提交；小时 cron 保留为幂等修复，而非正常的新鲜度时钟。已有 NULL 历史字节无法恢复；不得用估算伪造。
- 版本前提 0 是冲突，不是格式错误。授权优先级、batch 逐项错误及 MCP 工具错误信封保持不变。
- 本轮仅操作本地资源；不合并主线、不部署、不访问生产。允许推送的唯一分支为 `kb-round3`。

## 加法迁移

本轮新增 `migrations/0008_word_search.sql`；`0007_vector_sync_retries.sql` 属于已合并的上游基线，不修改其编号或内容：

| 对象 | 作用 |
|---|---|
| `memories_words_fts` | 保存预分词 title/body/tags 的 unicode61 FTS5；与 trigram 共用 rowid 映射 |
| `search_tag_tokens` | 标签名对应的预分词文本，随 memory 写入、标签改名/合并更新 |
| `search_backfill_state` | 单行持久化 tag/memory keyset 游标、阶段与完成状态 |

没有改名、删列、重写原始正文，也不在 migration 中同步全量分词。词索引保存 token 内容而不是 contentless，目的是让标签变更能在 SQL 原子事务内保留 title/body，仅更新 tags；其额外空间由基准单列量化。

MAX 审查拒绝了最初可选的全重叠双字窗口：有效的 960 KB 汉字正文能膨胀到超过 D1 的 2 MB 行限制。NFKC 也会把 960 KB 兼容字形扩大到 10.56 MB。因此最终实现保留完整分词、原词频和去重单字补充，不做正文兼容展开，也不通过截断 token、减少原始正文上限或漏掉旧行规避约束。新增 L1 长文本与真实 D1 写入边界回归。跨分词边界的双汉字查询通过单字索引候选加 LIMIT 前的同字段连续性校验补充；「周会议程」可匹配「周会」，「周末开会」不可，且不会恢复最新 N 条扫描。

## 回填操作手册

以下是未来获准上线时的操作步骤，不代表本轮已执行生产操作：

1. 先按顺序应用上游 0007 与本轮 0008 加法迁移，再完成使用新索引代码的 Worker 发布；确认旧代码的在途写入已结束。不要先发布依赖新表的代码。
2. 已认证且带同源 Origin 的管理员调用 `POST /api/admin/settings/search/backfill`，不传正文。API key 和 `/api/v1` 不能触发回填；Cloudflare Access 和写入 Origin 校验照常生效。
3. 每次响应为 `{tags, memories, complete}`；两种计数之和不超过 100。非回收站正文输入预算为 1 MiB，单条超过预算时仍允许单条前进。连续调用到 `complete=true`；不要无限并行请求。定时任务每小时也推进一次，50k 小记录约需 500 次，不能只等待 cron 然后立即声称历史数据已全量可搜。
4. 中断或失败后重新调用同一接口即可续跑。标签数据与标签游标、memory 索引与 memory 游标各自同批提交；不会把失败批次标为完成。并发触发不能倒退检查点；版本/更新时间条件阻止陈旧快照覆盖新写入。
5. 完成后再次调用应返回 `{tags:0, memories:0, complete:true}`。检查活跃记录的缺失索引数为 0，并用一个旧的二字词和一个多词问题验证实际召回。恢复回收站记录会在恢复事务中建立索引，无需为了恢复预先索引垃圾箱。

只读完整性核对 SQL：

```sql
SELECT tags_done, complete FROM search_backfill_state WHERE id = 1;
SELECT COUNT(*) AS missing
FROM memories m
LEFT JOIN memories_fts_map map ON map.memory_id = m.id
LEFT JOIN memories_words_fts words ON words.rowid = map.fts_rowid
WHERE m.deleted_at IS NULL AND words.rowid IS NULL;
```

上线回填期间旧记录尚未全量进入词索引是可预期的过渡状态；`partial=false, partial_reason=null` 表示不再采用有界短词扫描，不是初始化完成证明。应以 complete 和上述缺失数验收历史召回。旧 trigram 表继续保留；本轮没有 down migration、清空生产索引或兼容旧写入路径的承诺。

## 复现与验证

- 单测先复现「他早上喝什么」无法召回 500 条之后的旧答案，再验证分词索引；共享问句集有 16 个问题，覆盖无空格、含空格、混写、中文年龄/地点/时间及英文问句。独立回归覆盖「周会」「咖啡」的上下文分词差异、510 个干扰项、同字段连续性、标签与 AND/OR。
- L2 用真实 workerd API 建立答案与向量，放入 510 条更新的干扰项，在 fts/hybrid 中逐个验证首位答案。旧有排序、权限、变音符、原始 trigram 和 MCP 回归保留并更新新契约断言。
- 生命周期验证包括 create/update/move/trash/restore/purge、staged tags、标签改名/合并、事务失败回滚、并发写与回填竞态、持久化游标续跑及正文预算。
- 用量回归先建 50 次快照，再超过 50 次且推进 61 秒，核对 per-key calls/writes/bytes_in/bytes_out；另测流延迟跨 UTC 日、cron 修复与失败回滚。业务 batch spies 明确排除独立的审计 batch，但两者都真实执行，不删除审计或弱化业务原子性断言。
- 机器有高后台负载。测试仍保持原有断言、超时和覆盖率门槛；L1 按负载降低 `VITEST_MAX_WORKERS` 到 1，L2 本身串行。失败的环境/清理运行不计为通过。

以下结果捕获于变基到 `c662f62` 之前；冻结源码与原始 JSON 中保留当时的 `0007_word_search.sql` 路径。当前部署迁移编号已顺延为 `0008`，SQL 内容不变。原始性能样本不改写，也不冒充包含新向量重试触发器的变基后测量；本次续任务重新验证功能门禁与覆盖率。

正式运行于 2026-10-18 22:47:31–22:53:50（Asia/Shanghai）完成并释放 Miniflare。完整方法与限制见 [基准说明](../benchmarks/README.md)，原始样本见 [本轮 JSON](../benchmarks/results/2026-10-18T14-47-31-635Z-CxvmqE.json)。两份历史 50k 结果明确标为 superseded，不用旧实现的数据替代最终结果。


另有人工 `云桥` 路径夹具：故意从一条种子词索引移除整词 token，但保留原文和单字，制造 direct-empty/fallback-only 条件。其墙钟 p50/p95 为 67.76/103.98，D1 为 3/4；101 个单字候选中，未验证前 50 名没有目标，而 LIMIT 前原文校验能返回旧目标。**该目标不是完整产品词索引，也不是天然 ICU 边界证明。** 原生「周会议程」「咖啡豆」由独立 workerd 回归验证。两库原文相同，但这 101 条人工队列使语料不同于历史轮次，不能把轮次差异全部归因于源码修改；正常写入样本未删除词项。
